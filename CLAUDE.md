Portfolio templates live in `templates/`, one subdirectory per fictional subject's first name (e.g. `templates/hal/`, `templates/bryan/`). The subject of each template is a distinct person; the directory name matches their first name as written in the body of `sample.html`. The list of subjects and their majors is in `templates/templates.json` and `html/grad-gallery.html`. Each directory contains:

- `sample.html` — the original sample website (source of truth for design)
- `annotation.html` — **autogenerated** AI-annotated version with `data-*` attributes, original colors preserved; do not edit directly
- `annotated.html` — **autogenerated** color-normalized final output (annotation.html + color vars); do not edit directly

`annotated.html` is the only derived file the generator reads. Regenerate the pair with:

```
node scripts/preprocessSamples.mjs --skip-annotate   # deterministic colour pass, no AI
node src/renumberTemplateColorVars.mjs --write       # renumber --c-N by dominance
```

Both steps are required. `preprocessSamples` emits slots in colour-discovery order; the
renumber pass sorts them by dominance (count × chroma), which is what the positional
palette assumes. Omit `--skip-annotate` ONLY for a template that has no `annotation.html`
yet, and pass that template's name — a bare run re-annotates every template it is given,
and annotator-chosen `data-list` names are not stable between runs.

A per-directory `template.html` (an AI "analysis template" — the sample genericized to
placeholders, with a JSON design-analysis header) used to sit here too. Nothing ever read
it, and all 20 had gone stale against
`src/netlify/functions/ExtractExampleWebsiteTemplate.md`, so they were deleted. That prompt
is still live: it drives the analysis returned at runtime by the template path and offered
through the form's "↓ template.html" download button, which serves an API response rather
than a file on disk.

Non-template files (gallery pages, test files, marketing pages, etc.) remain in `html/`.
